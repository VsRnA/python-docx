# Текущее устройство сервиса

## Рабочий контур

1. Пользователь загружает DOCX.
2. API сохраняет исходник в S3 и ставит задание в очередь PostgreSQL.
3. Worker загружает prompt и PDF-образец опубликованной стилизации из профиля.
4. GPT Astra 6 возвращает HTML-документ.
5. Backend проверяет HTML, сохраняет изображения отдельно и создаёт первую версию.
6. Frontend показывает сохранённый HTML в изолированном iframe.
7. AI-правки, перевод, восстановление версий и публикация создают новые ревизии.

Для сценария слияния worker передаёт Astra исходные DOCX-файлы, промпт слияния и PDF-образец стилизации.

## Контракты

- HTML ограничен `HtmlContractValidator`.
- Редактируемые блоки идентифицируются `data-block-id`.
- Изображения в каноническом HTML обозначаются `asset://UUID`.
- Prompt выбранной стилизации хранится в базе данных и применяется к новым запускам.
- Опубликованная стилизация и её материалы не меняются уже созданными документами.

## Границы текущего контура

Сервис формирует и публикует HTML. Отдельный серверный рендеринг PDF и внешняя очередь
сообщений в рабочий контур не входят.
