# Техническое задание: web-сервис работы с документами

## Назначение

Сервис принимает заводские DOCX, преобразует их в единый фирменный HTML, позволяет редактировать
документ вручную и через AI, переводить его, формировать PDF и публиковать HTML.

## Пользовательский сценарий

1. Пользователь загружает DOCX размером до 50 МБ.
2. Сервис сохраняет оригинал и ставит обработку в очередь.
3. Worker формирует PDF-рендер исходного DOCX через изолированный LibreOffice-конвертер.
4. GPT Astra 6 получает полный DOCX, его визуальный PDF-рендер, PDF-эталон темы, обзорные листы
   эталона и версионированный HTML-контракт.
5. После обработки открывается редактор с A4-представлением документа.
6. Пользователь вручную редактирует документ или формулирует запрос AI-помощнику.
7. При необходимости пользователь переводит документ через YandexGPT.
8. Каждое изменение сохраняется отдельной ревизией; старую ревизию можно восстановить.
9. Пользователь выгружает PDF или публикует самодостаточную HTML-страницу.

## Функциональные требования

### Документы

- загрузка только валидных ZIP-based DOCX;
- список документов и статусы обработки;
- переименование и мягкое удаление;
- хранение оригинала в Timeweb S3;
- журнал фоновых задач с прогрессом и ошибкой.
- визуальный DOCX→PDF-рендер без семантического предварительного разбора;
- строгое разделение исходных файлов и стилевых эталонов в запросе к модели;
- запрет переноса текста, фактов и изображений из стилевого эталона;

### HTML-контракт

- разрешены только утвержденные теги, атрибуты и классы;
- запрещены script, iframe, inline style и event handlers;
- каждый изменяемый блок имеет уникальный `data-block-id`;
- изображения хранятся отдельно и обозначаются `asset://UUID`;
- тема и prompt package имеют неизменяемую версию;
- ответы модели проверяются строгой Pydantic/JSON Schema валидацией.

### Редактор

- Tiptap/ProseMirror;
- A4-полотно, разрывы страниц, toolbar, undo/redo;
- отсутствие пересоздания редактора при каждом вводе;
- debounce и последовательное автосохранение;
- блокировка конфликтующих действий во время AI-операции;
- адаптивная панель AI, перевода и версий;
- визуальная тема соответствует приложенному PDF: градиентная шапка, колонтитулы, оранжевые
  предупреждения, оглавление, двухколоночные блоки, таблицы, рисунки и подписи.

### AI-правки

- GPT Astra 6 получает текущий HTML, запрос, ревизию, хеши блоков, компоненты и классы темы;
- модель возвращает только change-set;
- неизмененные блоки не возвращаются и не переписываются;
- сервер проверяет ревизию и SHA-256 каждого целевого блока;
- новая или исправленная иллюстрация может возвращаться как base64 asset;
- результат проходит повторную HTML-валидацию.

### Перевод

- HTML разбивается только на текстовые сегменты;
- структура и идентификаторы блоков остаются неизменными;
- YandexGPT получает сегменты пакетами;
- сохраняются числа, единицы, обозначения, модели и XML-like ID сегментов;
- перевод сохраняется новой ревизией.

### Экспорт

- PDF формируется из текущей ревизии в отдельном изолированном renderer;
- размер страницы A4, печатный фон включен;
- внешняя сеть renderer заблокирована;
- HTML-публикация содержит встроенные CSS и изображения;
- публикации имеют неизменяемые S3-ключи и историю.

## Нефункциональные требования

- API не держит первичный разбор DOCX в web-процессе;
- максимальный размер исходного документа — 50 МБ;
- суммарный размер файловых входов OpenAI — не более 50 МБ;
- оптимистическая блокировка по ревизиям;
- OIDC/JWT в production, тестовый `X-User-ID` только вне production;
- доступ ко всем объектам проверяется через владельца документа;
- повтор временных ошибок OpenAI/сети с exponential backoff;
- конфиденциальные ключи передаются только через environment/secrets;
- исходники и пользовательские документы не попадают в Docker image;
- сервисы имеют health checks, миграции выполняются отдельным контейнером.

## Основные API

- `POST /api/v1/documents` — загрузка DOCX;
- `GET /api/v1/documents` — список;
- `GET/PATCH/DELETE /api/v1/documents/{id}` — чтение, переименование, удаление;
- `PUT /api/v1/documents/{id}/content` — сохранение HTML;
- `POST /api/v1/documents/{id}/ai-edits` — AI change-set;
- `POST /api/v1/documents/{id}/translations` — перевод;
- `GET /api/v1/documents/{id}/versions` — версии;
- `POST /api/v1/documents/{id}/versions/restore` — восстановление;
- `POST /api/v1/documents/{id}/exports/pdf` — PDF;
- `GET/POST /api/v1/documents/{id}/publications` — публикации;
- `GET /api/v1/jobs/{id}` — состояние задачи.

## Ограничение приемки

Реализация считается проверенной только после финального Docker-прогона. Наличие кода без сборки,
миграций, тестов и визуального сравнения PDF не считается подтверждением работоспособности.
