# План воспроизводимой верстки руководств A4

## Цель

Сервис должен преобразовывать заводской DOCX в редактируемый HTML и печатный PDF, визуально
соответствующие принятому результату MRZ 3560 PRO: A4, фирменная обложка, повторяющаяся шапка,
зеркальные колонтитулы, предупреждения, специализированные таблицы, галереи и сохраненные схемы.

Эталонный PDF определяет визуальный язык. DOCX остается единственным источником текста, чисел,
моделей и технических фактов. Замечания о противоречиях возвращаются отдельно и не добавляются в
руководство без явной команды пользователя.

## Этап 1. Каноническая тема и контракт

Статус: реализовано в коде.

- добавлен prompt package `docx-to-html/v2`;
- добавлена тема `villartec-manual-a4@1.0`;
- определены компоненты обложки, содержания, предупреждений, примечаний, таблиц, галерей,
  наложенных изображений и форм;
- внутренние ссылки содержания разрешены безопасным HTML-контрактом;
- inline CSS и полный HTML-документ по-прежнему запрещены в каноническом содержимом;
- каждое редактируемое содержимое обязано иметь стабильный `data-block-id`.

## Этап 2. Иллюстрации

Статус: базовая реализация выполнена, требуется интеграционный прогон.

- модель получает DOCX, визуальный PDF исходника и извлеченные изображения;
- после ответа модели изображения больше не удаляются и не переставляются по приблизительным
  `lastRenderedPageBreak`;
- контракт отклоняет полный документ, если хотя бы один переданный исходный asset не использован;
- overlay-компонент позволяет сохранять базовое изображение, стрелки, номера и подписи раздельно;
- для несовместимых сложных схем модель может вернуть один flattened replacement asset.

## Этап 3. Печатный движок

Статус: реализовано и проверено в Docker.

- renderer переведен с Chromium на WeasyPrint 68;
- внешний сетевой доступ при рендеринге запрещен;
- разрешены только материализованные `data:` изображения;
- тема использует CSS Paged Media, running header/footer и счетчики страниц;
- Lato устанавливается в образ renderer и используется детерминированно;
- renderer включен в Docker Compose как зависимость API и worker.

## Этап 4. Редактор

Статус: базовая поддержка реализована, production build frontend выполнен.

- полотно переведено на A4;
- добавлены Tiptap nodes для новых контейнеров темы;
- сохраняются `id` якорей и `href` строк содержания;
- добавлено экранное оформление галерей, overlay-изображений, форм и примечаний.

Динамическая экранная пагинация длинных разделов остается отдельной задачей. До ее реализации
редактор показывает минимальную страницу A4, которая может увеличиваться по высоте, а финальная
пагинация определяется WeasyPrint.

## Этап 5. Golden test

Статус: следующий этап.

1. Собрать полный Docker stack с тестовыми ключами OpenAI и Timeweb S3.
2. Загрузить `MRZ_3560_Pro_MownsterTM.docx` через публичный API.
3. Сохранить JSON-ответ модели, канонический HTML, материализованный HTML и PDF.
4. Проверить сохранность чисел, единиц, моделей, предупреждений, таблиц и всех исходных assets.
5. Отрендерить страницы PDF в PNG и сравнить с принятым `output.pdf`.
6. Исправлять только версионированные тему и prompt package; не добавлять специальные правила для
   текста конкретной модели газонокосилки.

## Критерии приемки

- PDF имеет размер A4 и не содержит обрезанного или перекрывающегося текста;
- обложка, шапка, подвалы, предупреждения и таблицы визуально соответствуют принятому результату;
- все технические числа и обозначения из DOCX сохранены либо отмечены в warnings;
- каждое переданное значимое изображение присутствует в логическом месте;
- HTML проходит контракт, остается редактируемым и не содержит внешних ресурсов;
- одинаковые версии prompt package, темы, шрифтов и renderer дают стабильный класс верстки;
- экспорт HTML и PDF использует одну и ту же каноническую ревизию.
